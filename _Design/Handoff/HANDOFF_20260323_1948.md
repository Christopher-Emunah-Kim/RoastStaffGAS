## 다음 세션 작업 목록

### [TASK 1] 오브젝트 풀링 서브시스템 구현

참고 코드(LunarRealm 프로젝트)를 기반으로 RoastStaff 프로젝트에 맞게 포팅.

#### 참고 코드 분석

**구조:**
```
UPoolingSubsystem (UWorldSubsystem)
├── SpawnPooledActor(Class, Transform) — 풀에서 꺼내거나 신규 SpawnActor
├── ReturnToPool(Actor)               — Destroy 대신 사용
├── InitializePool(Class, Count)      — 스테이지 시작 전 사전 워밍업
├── ReturnAllActiveActors()           — 스테이지 리셋 시 전체 반환
└── template<T> Spawn(Class, Transform) — C++ 타입 안전 헬퍼
```

**풀 흐름:**
```
SpawnPooledActor:
  1. ActorPool[Class]에서 유효한 액터 Pop
  2. 없으면 신규 SpawnActor
  3. SetActorTransform(SpawnTransform)
  4. OnPoolActivate() 호출 (IPoolableInterface)
  5. ActiveActors에 추가

ReturnToPool:
  1. ActiveActors에서 제거
  2. OnPoolDeactivate() 호출
  3. ActorPool[Class]에 Push
```

**데이터 구조:**
```cpp
TMap<UClass*, TArray<AActor*>> ActorPool;   // 클래스별 풀 스택
TSet<AActor*> ActiveActors;                  // 활성 액터 추적 (UPROPERTY 필요)
```

#### RoastStaff 포팅 시 주의사항

1. **클래스 접두사**: `URS` 사용 (`ULR_` 금지)
   - `URSPoolingSubsystem`, `IRSPoolableInterface`

2. **서브시스템 타입**: 참고 코드는 `UWorldSubsystem`.
   - 기존 프로젝트 서브시스템은 `UGameInstanceSubsystem` 패턴 (GDS, SGS, RDS, UMS)
   - 풀링은 월드 수명에 맞는 `UWorldSubsystem`이 더 적합 (스테이지 리셋 연동 용이)
   - **결정 필요**: GameInstance vs World 서브시스템

3. **인터페이스 구현 대상**:
   - `ABaseSummonObject` — BeginPlay 대신 `OnPoolActivate`에서 GE 적용
   - `ABaseProjectile` — 기존 투사체에도 적용 가능

4. **`ActiveActors` UPROPERTY 누락 버그**:
   - 참고 코드에서 `ActiveActors`에 `UPROPERTY()` 없음 → GC 위험
   - 포팅 시 반드시 `UPROPERTY()` 추가할 것

5. **`OnPoolActivate` / `OnPoolDeactivate` 설계**:
   - `ABaseSummonObject::OnPoolActivate` → `SetLifeSpan(Lifetime)` + `ApplyGameplayEffectToArea()`
   - `ABaseSummonObject::OnPoolDeactivate` → `SetActorHiddenInGame(true)`, 타이머 초기화

6. **`InitializePool` 호출 위치**:
   - Stage 시작 시점 (GameMode or StageSubsystem)에서 호출
   - 소환 오브젝트 BP 클래스 목록을 미리 워밍업

// SetSlotActive: 소환형 슬롯 활성화 시 즉시 FireSlot

    SetTimer(AutoFireTimerHandle, 0.1f, false)  // EndAbility 완료 보장 딜레이

}
else
{
    SetTimer(AutoFireTimerHandle, Cooldown, true)  // 자동 반복
}
