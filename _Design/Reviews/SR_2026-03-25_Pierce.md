## 핵심 버그 (수정 전 머지 불가)

### 버그 1 — switch fall-through (GA_ProjectileAttack.cpp, L142~154)
`case EHitType::PIERCE` 블록에 `break` 누락. 현재는 `default`가 비어있어 런타임 오류는 없으나,
향후 `default`에 로직 추가 시 PIERCE가 의도치 않은 분기를 실행함. 컴파일러 경고(-Wimplicit-fallthrough) 대상.

### 버그 2 — HitCount 계산의 발사자 포함 오염 (BaseProjectile.cpp, L371~372) [기획서 불일치]
`MoveIgnoreActors`에는 `InitProjectile`에서 먼저 등록된 **발사자(AvatarActor)**가 항상 포함됨.
`CopyArrayOfMoveIgnoreActors().Num()`로 HitCount를 계산하면 첫 번째 적 타격 시 HitCount=2.

**기획서 요구사항:** "첫 번째 대상은 데미지 100%"
**실제 동작:** `Multiplier = 1.f - (2-1)*0.7 = 0.3f` → 30% 데미지

PierceCount 한도 비교(`HitCount >= PierceCount`)도 동일하게 오염됨.
CSV PierceCount=4 설정 시 실제 3회만 관통.

## 개선 제안

### HitCount 추적 전략 재설계 (버그 2 해결 방법)
`MoveIgnoreActors`는 물리 충돌 무시 배열이지 카운터가 아님. 별도 `int32 PierceHitCount` 멤버 변수로 분리:

```cpp
// BaseProjectile.h private 섹션
int32 PierceHitCount = 0;

// HandlePierceHit 내
SphereComp->IgnoreActorWhenMoving(OtherActor, true);  // 중복 방지 전용
PierceHitCount++;                                       // 카운팅 전용
const float Multiplier = FMath::Max(0.f, 1.f - (PierceHitCount - 1) * InitData.DamageDecay);
if (PierceHitCount >= InitData.PierceCount)
{
    bHasPierceFinished = true;
    ReturnToPool();
}

// OnPoolDeactivate
PierceHitCount = 0;
```

### FSkillAttackHitTypeParamsPierce 기본값
```cpp
int32 PierceCount = 1;   // 최소 1회 보장
float DamageDecay = 0.f; // 기본값: 감쇠 없음
```

### OnHit의 PIERCE 명시적 분기
```cpp
case EHitType::PIERCE:
    return;  // PIERCE는 OnBeginOverlap에서 처리. 벽 충돌 시 통과
```

## 통과 항목
- OnPoolDeactivate의 ClearMoveIgnoreActors + bHasPierceFinished 리셋 — 풀링 재사용 오염 방지
- bHasPierceFinished 이중 ReturnToPool 방지 플래그
- OnBeginOverlap에서 HitType PIERCE 가드
- HandlePierceHit의 FMath::Max(0.f, ...) Multiplier 음수 방지
- PierceCount, DamageDecay UPROPERTY() 적용 (이전 리뷰 패턴 개선)
- OnProjectileInitialized에서 PIERCE 시 ECR_Overlap 전환 (OnComponentHit 투사체 정지 버그 교훈 반영)
- ASC 없는 오브젝트(벽/지형) 통과 처리
