# GameFlow_Architecture
```yaml
version:  1.0
date:     2026-03-31
source:   Lunar_Realm (UE5, C++)
purpose:  >
  이식용 참조 문서. 다른 게임 프로젝트의 Claude Code가 읽고
  Intro→OutGame→InGame 흐름을 재구현할 때 사용.
  "현재 게임(Lunar_Realm)" = 참조 구현체.
  "신규 게임" = 이식 대상.
scope:
  - 게임 시작부터 스테이지 진입까지 전체 호출 흐름
  - GameInstance 스코프 Subsystem 의존성 및 초기화 순서
  - 신규 구현 필요 시스템: SaveGameSubsystem, RuntimeDataSubsystem
  - UI 레이어 설계(EUIID + 4-Layer)
  - TransitionGameMode 비동기 에셋 프리로드 패턴
out_of_scope:
  - InGame 전투 로직
  - PoolingSubsystem, EquipmentSubsystem, LevelUpSubsystem 내부 구현
  - GAS(Gameplay Ability System) 연동
```

---

## 1. ARCHITECTURE_OVERVIEW

### 1-1. 레벨 구성
```yaml
levels:
  INTRO:      PlayerController=IntroController,      GameMode=IntroGameMode(or Base)
  TRANSITION: PlayerController=TransitionController, GameMode=TransitionGameMode
  OUTGAME:    PlayerController=OutGameController,    GameMode=OutGameMode
  STAGE:      PlayerController=InGameController,     GameMode=InGameMode
  # TRANSITION은 실제 씬 전환 없이 로딩 화면 + 에셋 프리로드를 담당하는 중간 레벨
  # MapSettings(DeveloperSettings)에 ELevelName → TSoftObjectPtr<UWorld> 매핑 보관
```

### 1-2. Subsystem 토폴로지
```
GameInstance (앱 생명주기 = 레벨 전환에도 유지)
  ├── GameDataSubsystem       [정적 데이터 읽기 전용]
  ├── SaveGameSubsystem       [파일 I/O 전담] ──────────────→ disk
  ├── RuntimeDataSubsystem    [런타임 상태 단일 진실 공급원]
  │     └── SaveGameSubsystem 초기 데이터로 하이드레이션
  │     └── 변경 시 즉시 in-memory 반영 (파일 쓰기는 SaveSys에 위임)
  ├── UIManagerSubsystem      [UI 생명주기 · 레이어 관리]
  ├── StageManagerSubsystem   [현재 스테이지 메타데이터]
  ├── PoolingSubsystem        [오브젝트 풀]
  ├── EquipmentSubsystem      [장비 계산 로직]
  └── LevelUpSubsystem        [레벨업/경험치 계산 로직]
```

### 1-3. 핵심 설계 원칙
```yaml
principles:
  - "GameDataSubsystem = 정적(읽기전용). 절대 변경하지 않음."
  - "SaveGameSubsystem = 파일 I/O 전담. 게임 로직이 이 시스템을 직접 변경하지 않음."
  - "RuntimeDataSubsystem = 런타임 상태의 단일 진실 공급원(SSOT). 모든 상태 변경은 여기."
  - "UIManagerSubsystem = GameInstance 스코프. 레벨 전환 후에도 캐시 유지."
  - "TransitionGameMode = RuntimeDataSubsystem 단일 참조로 프리로드 에셋 수집."
  - "레벨 전환 전 UIManager.ResetAllUIStates() 반드시 호출."
```

## 2. SUBSYSTEM_INIT_ORDER

```
GameInstance::Init()
  │
  ├─[1] GameDataSubsystem::Initialize()
  │       - DataTable / CurveTable 로드 및 캐싱
  │       - 의존: 없음
  │
  ├─[2] SaveGameSubsystem::Initialize()
  │       - Collection.InitializeDependency<GameDataSubsystem>() 선언
  │       - LoadGame() 즉시 실행 → 파일 있으면 로드, 없으면 CreateNewSaveGame()
  │       - OnSaveGameLoadedDel 브로드캐스트
  │       - 의존: GameDataSubsystem
  │
  ├─[3] RuntimeDataSubsystem::Initialize()        ← 신규 구현
  │       - Collection.InitializeDependency<GameDataSubsystem>()
  │       - Collection.InitializeDependency<SaveGameSubsystem>()
  │       - SaveSys.OnSaveGameLoadedDel 구독 → HandleSaveGameLoaded()
  │       - 이미 SaveGame 있으면 수동으로 HandleSaveGameLoaded() 호출
  │       - 의존: GameDataSubsystem, SaveGameSubsystem
  │
  ├─[4] UIManagerSubsystem::Initialize()
  │       - 캐시 초기화
  │       - 의존: 없음 (단, GetOrCreate 시점에 PlayerController 필요)
  │
  ├─[5] StageManagerSubsystem::Initialize()
  │       - 의존: GameDataSubsystem
  │
  └─[6] EquipmentSubsystem, LevelUpSubsystem, PoolingSubsystem
          - 의존: 각자 선언
          # 이 문서는 내부 구현을 다루지 않음. 이식 대상에 이미 존재함.

# IMPORTANT: InitializeDependency 선언 없이 단순 GetSubsystem 호출 시
#            초기화 순서 미보장 → 반드시 의존 선언할 것.
```

## 3. CALL_FLOW

### 3-1. INTRO 레벨

```
[앱 실행 → INTRO 레벨 로드]
  │
  ▼
ALRControllerBase::BeginPlay()
  └→ OpenFirstWidget()  ← 자식에서 override

ALRIntroController::OpenFirstWidget()
  ├→ UIManager.OpenUIByID(EUIID::BACKGROUND)   // PERSISTENT 레이어, 배경 위젯
  └→ UIManager.OpenUIByID(EUIID::INTRO)        // PAGE 레이어, 인트로 애니메이션

  [인트로 위젯 BP 내부]
    BindToAnimationEvent(FadeAnim, Finished)
    PlayAnimation(FadeAnim)
      └→ [애니메이션 종료 이벤트]
           └→ SetTimer → ALRIntroController::OpenTitleScreen()
                └→ UIManager.OpenUIByID(EUIID::TITLE)  // PAGE 레이어

  [타이틀 화면 "게임 시작" 버튼]
    └→ GI::OpenNextLevelByName(ELevelName::OUTGAME)
         └→ [SEE 3-3 TRANSITION FLOW]
```

### 3-2. OUTGAME 레벨

```
[OUTGAME 레벨 로드]
  │
  ▼
ALROutGameMode::BeginPlay()  // 현재 거의 비어있음. 필요 시 확장.

ALROutGameController::OpenFirstWidget()
  ├→ UIManager.OpenUIByID(EUIID::OUTGAME)   // PERSISTENT 레이어, 공통 오버레이 프레임
  ├→ UIManager.ClearUIHistory()
  ├→ UIManager.OpenUIByID(EUIID::LOBBY)     // PAGE 레이어, 로비 메인
  └→ PlaySound2D(LobbyBGM)

  [로비 내 파티 편성]
    OutGameController::OnSelectedEntryWidget(EntryWidget)
      ├─ EntryWidget = CHARACTER
      │    └→ SaveGameSubsystem::SetPartySlot(index, CharID)
      └─ EntryWidget = EQUIPMENT
           └→ RuntimeDataSubsystem::GetEquipmentInstancesByKey(EquipID)
                → SaveGameSubsystem::SetLeaderEquipmentSlot(index, GUID)
    # 신규 게임에서는 SaveSys 직접 호출 대신 RuntimeDataSubsystem 경유 권장
    # RuntimeDS::SetPartySlot() → 내부에서 SaveSys 동기화

  [스테이지 진입]
    GI::OpenNextStage(StageID)
      ├→ GI::SetNextLevelName(ELevelName::STAGE)
      ├→ GI::SetNextStageID(StageID)
      ├→ StageManagerSys::LoadStage(StageID)   // 스테이지 메타데이터 세팅
      └→ GI::OpenNextLevelLatent()
           └→ [SEE 3-3 TRANSITION FLOW, target=STAGE]
```

### 3-3. TRANSITION 레벨 (공통 레벨 전환 흐름)

```
GI::OpenNextLevelLatent()
  └→ SetTimer(0.1s)
       ├→ UIManager.ResetAllUIStates()   // 캐시 파괴, 모든 위젯 제거
       └→ OpenLevel(ELevelName::TRANSITION)

[TRANSITION 레벨 로드]
  │
  ▼
ALRTransitionController::OpenFirstWidget()
  └→ UIManager.OpenUIByID(EUIID::LOADING)   // 로딩 화면 표시

ALRTransitionGameMode::BeginPlay()
  ├→ UIManager.GetOrCreateWidgetByID(EUIID::LOADING) → LoadingWidget 캐싱
  ├→ LoadingWidget.SetLoadingProgress(0.0f)
  ├→ GI::GetNextLevelName() → TargetLevelName
  └→ PreloadAssetsAsync()

PreloadAssetsAsync():
  ├─ [신규 게임] RuntimeDataSubsystem::GatherPreloadAssets(OutPaths)
  │     // 내부 구현은 4-3 참조
  │     // Character Mesh, AnimBP, SkillVFX/SFX
  │     // [if target==STAGE] Enemy Mesh, Anim, Sound, SkillVFX
  │     // Chapter/Stage 썸네일 등 UI 에셋
  │
  ├─ [참조: Lunar_Realm 현재 구현]
  │     SaveSys::GetAllPartyCharactersIDs()
  │       → DataSys::GetCharacterStaticData(ID) → Mesh, AnimBP, SkillResources
  │     DataSys::GetChapterStaticData(ID) → Thumbnail, Background
  │     [if target==STAGE]
  │       StageManagerSys::GetCurrentStateData() → SpawnEnemyIDs, BossEnemyID
  │         → DataSys::GetEnemyStaticData(ID) → Mesh, Anim, AttackMontages, AuraVFX
  │         → DataSys::GetEnemySoundData(ID) → DeathSound, AttackSounds, etc.
  │
  ├─ AssetsToLoad.Num() > 0
  │     AssetManager::RequestAsyncLoad(AssetsToLoad)
  │       └→ callback: StartLevelStreaming()
  │
  └─ AssetsToLoad.Num() == 0
       └→ StartLevelStreaming() 직접 호출

StartLevelStreaming():
  └→ GameplayStatics::LoadStreamLevel(TargetLevel, false, false, LatentInfo)
       └→ callback: OnLevelPreloadCompleted()

Tick() 중:
  bIsLoadingLevel == true 동안:
    CurrentFakeProgress = FInterpTo(Current, 0.9f, Delta, 1.5f)  // 최대 90%까지
    LoadingWidget.SetLoadingProgress(CurrentFakeProgress)

OnLevelPreloadCompleted():
  ├→ bIsLoadingLevel = false
  ├→ LoadingWidget.FinishLoading()          // 100% + 완료 연출
  └→ SetTimer(1.0s) → OpenLevel(TargetLevel)

[스테이지 클리어/실패 후 귀환]
  └→ GI::OpenNextLevelByName(ELevelName::OUTGAME)
       └→ TRANSITION 흐름 동일하게 반복 (target=OUTGAME, Enemy 수집 없음)
```

## 4. SUBSYSTEM_SPECS

### 4-1. GameDataSubsystem
```yaml
role: >
  정적 DataTable 데이터를 로드·캐싱하고 조회 API를 제공.
  절대 변경되지 않음(읽기 전용 SSOT).
pattern_current(Lunar_Realm): >
  단일 조회: GetCharacterStaticData(ID), GetSkillStaticData(ID), GetEnemyStaticData(ID) 등
  각 호출자가 여러 API를 조합해서 사용.
pattern_new(권장): >
  복합 조회: 외부 public API를 최소화하고 private helper 조합으로 완성된 데이터를 반환.
  예) GetCharacterPreloadBundle(CharID) → FCharacterPreloadBundle { Mesh, AnimBP, SkillPaths[] }
      GetStageSpawnBundle(StageID)     → FStageSpawnBundle { EnemyBundles[], BossBundle }
  장점: TransitionGM, RuntimeDS 등 호출자가 DataSys 내부 구조를 알 필요 없음.
init_dependency: none
note: >
  신규 게임에 이미 존재. API 형태만 다름. 이식 시 조회 API 호환성 확인 필요.
```

### 4-2. SaveGameSubsystem
```yaml
role: "파일 I/O 전담. 게임 로직은 이 시스템을 직접 변경하지 않는다."
init_dependency: [GameDataSubsystem]
status: "신규 구현 필요"

lifecycle:
  Initialize: LoadGame()
  Deinitialize: SaveGame()  # 앱 종료 시 자동 저장

key_events:
  OnSaveGameLoadedDel: "로드 완료 시 브로드캐스트 → RuntimeDataSubsystem이 구독"
  OnSaveGameSavedDel:  "저장 완료 시 브로드캐스트 (선택)"

data_owned:
  - "파티 슬롯 (캐릭터 ID 배열, 크기=파티 최대 인원)"
  - "장비 슬롯 (Equipment Instance GUID 배열)"
  - "보유 캐릭터 목록 (ID → 레벨/경험치/해금 여부)"
  - "보유 장비 목록 (GUID → EquipmentID/레벨/경험치)"
  - "재화 (골드, 가챠 티켓 등)"
  - "진행 기록 (클리어된 스테이지 ID 목록 등)"

save_trigger_policy:
  - "Deinitialize (앱 종료)"
  - "스테이지 클리어/실패 결과 확정 시"
  - "명시적 저장 지점 (설정 변경, 가챠 결과 등)"
  - "NEVER: 매 프레임, 매 로비 조작"

serialization_pattern: |
  // RuntimeDataSubsystem이 직렬화 데이터를 제공하는 방식 권장
  void USaveGameSubsystem::SaveGame()
  {
      URuntimeDataSubsystem* RuntimeDS = GI->GetSubsystem<URuntimeDataSubsystem>();
      RuntimeDS->SerializeToPersistentData(CurrentSaveGame);  // RuntimeDS → SaveGame 동기화
      UGameplayStatics::SaveGameToSlot(CurrentSaveGame, SlotName, 0);
  }
```

### 4-3. RuntimeDataSubsystem
```yaml
role: >
  런타임 상태의 단일 진실 공급원(SSOT).
  도감 해금 정보, 캐릭터/장비 인스턴스 데이터를 메모리에 보관.
  모든 게임 로직은 이 시스템을 읽고 씀.
  (Lunar_Realm의 CollectionSubsystem과 개념적으로 동일하나 SaveGame 동기화 책임까지 포함)
init_dependency: [GameDataSubsystem, SaveGameSubsystem]
status: "신규 구현 필요"

init_pattern: |
  void URuntimeDataSubsystem::Initialize(FSubsystemCollectionBase& Collection)
  {
      Collection.InitializeDependency<UGameDataSubsystem>();
      Collection.InitializeDependency<USaveGameSubsystem>();
      Super::Initialize(Collection);

      USaveGameSubsystem* SaveSys = GI->GetSubsystem<USaveGameSubsystem>();
      SaveSys->OnSaveGameLoadedDel.AddDynamic(this, &ThisClass::HandleSaveGameLoaded);

      // SaveGame이 이미 로드된 경우 즉시 하이드레이션
      if (UYourSaveGame* Save = SaveSys->GetCurrentSaveGame())
          HandleSaveGameLoaded(Save);
  }

hydration_pattern: |
  void URuntimeDataSubsystem::HandleSaveGameLoaded(UYourSaveGame* Save)
  {
      // 1. GameDataSubsystem에서 전체 ID 목록 조회
      // 2. 모든 캐릭터/장비 RuntimeInstance 생성 (기본값: 미해금, Lv1)
      // 3. Save 데이터로 해금 여부·레벨·경험치 덮어쓰기
      // → 이후 런타임 상태는 SaveGame이 아닌 이 시스템에서 조회
  }

serialization_pattern: |
  void URuntimeDataSubsystem::SerializeToPersistentData(UYourSaveGame* OutSave)
  {
      // RuntimeInstance → SaveGame 구조체로 직렬화
      // SaveGameSubsystem::SaveGame()이 이 함수를 호출함
  }

key_apis:
  read:
    - "GetCharacterInstance(FName CharID) → FCharacterInstance"
    - "GetEquipmentInstance(FGuid InstanceID) → FEquipmentInstance"
    - "GetEquipmentInstancesByKey(FName EquipID) → TArray<FEquipmentInstance>"
    - "GetPartyCharacterIDs() → TArray<FName>"
    - "GetPartyPreloadPaths(TArray<FSoftObjectPath>& Out)  ← TransitionGM이 호출"
  write:
    - "SetPartySlot(int32 Index, FName CharID)           → SaveSys에 즉시 동기화 여부는 정책에 따름"
    - "SetLeaderEquipmentSlot(int32 Index, FGuid GUID)"
    - "UnlockCharacter(FName CharID)"
    - "UnlockEquipment(FName EquipID) → FEquipmentInstance 생성 후 추가"
    - "AddCharacterExp(FName CharID, int32 Exp)"

data_owned:
  characters: "TMap<FName, FCharacterInstance>  (전체 캐릭터, 해금 여부 포함)"
  equipments: "TMap<FGuid, FEquipmentInstance>  (보유 장비 인스턴스, GUID 키)"
  party_slots: "TArray<FName>                   (선택된 파티 캐릭터 ID)"
  equip_slots: "TArray<FGuid>                   (선택된 장비 슬롯 GUID)"

gather_preload_assets_spec: |
  // TransitionGameMode가 호출. GameDataSubsystem의 복합조회 API 활용.
  void URuntimeDataSubsystem::GatherPreloadAssets(
      TArray<FSoftObjectPath>& OutPaths,
      bool bIncludeEnemies,                  // target==STAGE 시 true
      const TArray<FName>& EnemyIDsToLoad    // StageManagerSys에서 제공
  )
  {
      // 파티 캐릭터 에셋
      for (FName CharID : GetPartyCharacterIDs())
      {
          FCharacterPreloadBundle Bundle = GameDataSys->GetCharacterPreloadBundle(CharID);
          OutPaths.AddUnique(Bundle.Mesh.ToSoftObjectPath());
          OutPaths.AddUnique(Bundle.AnimBP.ToSoftObjectPath());
          for (auto& SkillPath : Bundle.SkillAssetPaths)
              OutPaths.AddUnique(SkillPath);
      }
      // UI 에셋 (Chapter 썸네일 등)
      GameDataSys->GatherUIAssetPaths(OutPaths);
      // 적 에셋 (스테이지 진입 시)
      if (bIncludeEnemies)
          for (FName EnemyID : EnemyIDsToLoad)
              GameDataSys->GetEnemyPreloadBundle(EnemyID).AppendTo(OutPaths);
  }
```

### 4-4. UIManagerSubsystem
```yaml
role: "UI 생명주기 및 레이어 관리. GameInstance 스코프로 레벨 전환 후에도 캐시 유지."
init_dependency: none
status: "신규 게임에 기존 구현 있음. 레이어 체계만 아래 명세로 정비 필요."

layer_design:
  PERSISTENT: "ZOrder=100. HUD 등 항상 표시. PermenentUIMap에 보관."
  PAGE:       "ZOrder=200. 메인 콘텐츠 1개. 전환 시 이전 PAGE 닫힘. UIHistory 스택."
  POPUP:      "ZOrder=300+. 모달 스택. 포커스 관리, ESC=CloseTopPopup."
  SYSTEM:     "ZOrder=500. 종료 확인, 에러 등. 항상 최상위."

euiid_spec: |
  // 신규 게임 EUIID 최소 목록 (필요에 따라 확장)
  UENUM(BlueprintType)
  enum class EUIID : uint8
  {
      NONE,
      LOADING,     // PAGE  — Transition 레벨 로딩 화면
      INTRO,       // PAGE  — 인트로 애니메이션
      TITLE,       // PAGE  — 타이틀 (게임 시작 버튼)
      OUTGAME,     // PERSISTENT — OutGame 공통 오버레이
      LOBBY,       // PAGE  — 로비 메인
      // ... 게임별 PAGE/POPUP 추가
      SETTING,     // POPUP
      PAUSE,       // POPUP
      GAMEOVER,    // SYSTEM
      GAMECLEAR,   // SYSTEM
      EXIT,        // SYSTEM
  };

  // UIManagerSettings (DeveloperSettings)
  // TMap<EUIID, TSoftClassPtr<UBaseWidget>> UIClassMap   ← BP에서 설정
  // TMap<EUIID, EUILayer>                  UILayerMap   ← BP에서 설정 (위젯 BP 내부 프로퍼티 대신)

caching_check: |
  // 이식 시 확인 항목:
  // [ ] GetOrCreateWidget이 CachedWidgets 에 위젯을 보관하는가
  // [ ] CloseUI가 RemoveFromViewport만 하고 위젯을 파괴하지 않는가
  // [ ] ResetAllUIStates가 레벨 전환 전 반드시 호출되는가
  // [ ] OpenUIByID(EUIID) → UIClassMap + UILayerMap 참조하여 처리하는가

key_apis:
  - "OpenUI<T>(TSubclassOf<T>)          → 캐시에서 꺼내거나 생성 후 레이어별 처리"
  - "OpenUIByID(EUIID)                  → UIClassMap 참조"
  - "CloseUI(Widget*) / CloseUI<T>()    → 레이어별 제거, 캐시 유지"
  - "CloseTopPopupUI()                  → ESC 핸들러용"
  - "CloseAllPopupUI()                  → 씬 전환 직전 정리"
  - "ResetAllUIStates()                 → 레벨 전환 직전 호출 (캐시 파괴)"
  - "SwitchPageUI<T>()                  → 현재 PAGE 닫고 새 PAGE 열기"
  - "ShowBackgroundUI() / HideBackgroundUI()"
```

### 4-5. StageManagerSubsystem
```yaml
role: "현재 선택된 스테이지 메타데이터를 보관하고 제공."
init_dependency: [GameDataSubsystem]

relationship_with_other_systems:
  GameDataSubsystem: |
    LoadStage(StageID) 호출 시 GameDataSubsystem에서 FStageStaticData 조회.
    이후 GetCurrentStateData()로 스테이지 데이터 제공.
  RuntimeDataSubsystem: |
    TransitionGameMode::PreloadAssetsAsync()에서
    StageManagerSys::GetCurrentStateData() → SpawnEnemyIDs / BossEnemyID 수집.
    RuntimeDS::GatherPreloadAssets(bIncludeEnemies=true, EnemyIDs)에 전달.
    → RuntimeDS가 GameDataSys에서 에셋 경로 수집.
  SaveGameSubsystem: |
    직접 의존 없음.
    스테이지 클리어 기록은 RuntimeDS → SaveSys 경로로 저장.
  UIManagerSubsystem: |
    직접 의존 없음.
    스테이지 선택 UI(DUTY 등)는 StageManagerSys를 조회해 표시.

call_sequence_stage_enter: |
  1. 로비 UI에서 StageID 선택
  2. GI::OpenNextStage(StageID)
       └→ StageManagerSys::LoadStage(StageID)   // GDS에서 스테이지 데이터 캐싱
       └→ GI::SetNextLevelName(STAGE)
       └→ OpenNextLevelLatent()
  3. TRANSITION 레벨: PreloadAssetsAsync()
       └→ StageManagerSys::GetCurrentStateData() → EnemyIDs
       └→ RuntimeDS::GatherPreloadAssets(true, EnemyIDs)
  4. 로드 완료 → OpenLevel(STAGE)
```

## 6. TRANSITION_PRELOAD

### 6-1. 패턴 요약
```
TransitionGameMode::BeginPlay()
  └→ PreloadAssetsAsync()
       ├─ RuntimeDS::GatherPreloadAssets() → TArray<FSoftObjectPath>
       ├─ AssetManager::RequestAsyncLoad(Paths, Callback=StartLevelStreaming)
       └─ [Paths 없음] → StartLevelStreaming() 직접 호출

Tick(): FakeProgress 인터폴레이션 (0 → 0.9, speed=1.5) → LoadingWidget 업데이트

StartLevelStreaming():
  └→ LoadStreamLevel(TargetLevel, LatentInfo) → OnLevelPreloadCompleted()

OnLevelPreloadCompleted():
  ├→ LoadingWidget::FinishLoading()   // 100% + 완료 연출
  └→ SetTimer(1.0s) → OpenLevel(TargetLevel)
```

### 6-2. FakeProgress 이유
```yaml
reason: >
  LoadStreamLevel이 완료돼도 위젯이 즉시 사라지면 UX가 어색함.
  실제 로딩 진행도를 퍼센트로 노출하기 어려운 경우 FakeProgress로 시각적 피드백 제공.
  완료 신호 수신 시 FinishLoading()으로 100% 확정 후 잠시 대기.
max_fake_progress: 0.9  # 100%는 OnLevelPreloadCompleted에서만 확정
wait_after_finish:  1.0s
```

### 6-3. 이식 시 에셋 수집 확장 포인트
```yaml
# GatherPreloadAssets 내부에서 수집 대상 추가 가능
extensible_targets:
  - "파티 캐릭터 Mesh / AnimBP / SkillVFX"
  - "Chapter/Stage UI 썸네일"
  - "보스 에셋 (스테이지 진입 시)"
  - "배경음악 (필요 시)"
  - "커스텀 에셋 (게임별 추가)"
```
