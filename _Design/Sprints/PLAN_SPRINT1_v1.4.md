## 구현 목표 요약 / 플레이 시나리오

**범위:** 레벨업 → 무기 획득 → 슬롯 장착 → 스킬 발사 파이프라인

- 플레이어가 테스트 버튼을 누르면 레벨이 오르고, 그때마다 무기 1종이 랜덤으로 주어져 빈 슬롯에 자동 장착된다.
- 장착된 무기는 플레이어의 입력이 없으면 자동으로 마우스 에임 방향으로 스킬을 발동한다. 아무것도 하지 않아도 전투가 유지된다.
- Num1/2/3 키로 특정 슬롯을 지정하면 그 슬롯만 자동 발사가 멈추고, 마우스 클릭으로 직접 조준해서 수동모드로 스킬을 발동한다.
- 각 슬롯의 쿨타임은 독립적으로 판정되며, 같은 무기를 두 슬롯에 꽂아도 쿨타임은 개별적으로 판단한다.
- 스킬의 동작방식과 사용 오브젝트, 수치는 전부 데이터 테이블에서 로드하여 사용한다.
- 기본적으로 레벨업 → 장착 → 발사 파이프라인 전체가 끊기지 않고 돌아가는지 검증하는 것을 이번 스프린트의 목표로 한다.

**기획 개념어 정의**

| 개념어 | 설명 |
| --- | --- |
| 스킬 실행 단위 (SEU) | 스킬 1회 발동을 담당하는 논리 단위. 발동/효과 적용/종료 모두 처리 |
| 효과 적용 단위 (EAU) | 캐릭터 속성을 변경하는 단일 효과. 데미지/쿨타임 등이 각각 별도의 EAU로 적용된다 |
| 능력 관리 컴포넌트 (AMC) | 캐릭터가 보유한 스킬 등록/발동/상태이상 수신을 관리하는 컴포넌트 |
| 상태 조건 식별자 (Tag) | 캐릭터 또는 스킬에 부여된 상태를 나타내는 계층형 문자열 식별자 (예: State.Dead, Skill.Fireball) |
| 스킬 마스터 데이터 | CSV에서 로드되는 스킬 관련 정적 데이터 테이블 전체 |
| 스킬 등록 핸들 | 캐릭터에 등록된 스킬 실행 단위를 식별하는 고유 토큰. 무기 해제 시 이 토큰을 이용해 스킬을 AMC에서 제거한다 |

    ```
        │                                    ▼
        │                          [GDS에서 DT_Skill 조회]
        │                          → SkillID로 GA클래스, 투사체클래스,
        │                            DamageGE, StatusGE 경로 획득
        │                                    │
        │                                    ▼
        │                          [TSoftClassPtr 동적 로드]
        │                                    │
        │                                    ▼
        │                          [ASC에 GA 부여 (GiveAbility)]
        │                          → FGameplayAbilitySpecHandle 저장
        │                                    │
        │                                    ▼
        │                          [자동공격 타이머 시작]

        │                                    │
        │                                    ▼
        │                          [로그 출력]
        │                          "Weapon Equipped: {WeaponID} → Slot {N}"
        │
        └─ 빈 슬롯 없음 ──────────────────────┐
                                             ▼
                                    [로그 출력]
                                    "All slots full. Weapon discarded: {WeaponID}"
    ```
    

**슬롯 활성화 + 공격 플로우**

- 플로우 차트
    
    ![image.png](image%201.png)
    
- Raw
    
    ```
    [기본 상태]
      슬롯 0, 1, 2 → 전부 자동공격 (쿨타임 타이머 기반)
      액티브 슬롯 인덱스 = -1 (없음)

        │
        ▼
    [액티브 슬롯 전환 판정]
        ├─ 현재 액티브 == 슬롯0 → 액티브 해제, 슬롯0 자동공격 복귀
        └─ 현재 액티브 != 슬롯0 → 기존 액티브 슬롯 자동공격 복귀
                                   슬롯0을 액티브로 전환
                                   슬롯0 자동공격 타이머 중지
        │
        ▼
    [슬롯0 액티브 상태]
      슬롯 0: 마우스 클릭 대기 (수동 발사)
      슬롯 1, 2: 자동공격 유지
    
    [마우스 좌클릭]
        │
        ▼
    [액티브 슬롯(0) 쿨타임 체크]
        ├─ 쿨타임 중 → 로그 "Slot 0: Cooldown remaining {N}s" + 발사 거부
        └─ 쿨타임 완료 → GA 활성화 (SendGameplayEvent)
                         → 투사체 스폰 or 소환형 즉시 시전
                         → 쿨타임 타이머 시작
                         → 로그 "Slot 0: Skill fired! CD: {N}s"
    ```

# 레벨업 시스템

**시스템 간단 요약**

- **레벨 수치 보유** : 플레이어의 현재 레벨을 관리하고, 레벨업 트리거에 따라 레벨업 발생 시 수치를 증가시킵니다.
- **무기 요청** : 레벨업 발생 즉시 무기 시스템에 새 무기 선정을 요청합니다.
- **레벨업 피드백** : 레벨업 발생 시 이펙트와 로그로 플레이어에게 알립니다.

**구현해야할 시스템 구현 목록**

| **시스템 구성 요소** | **설명** |
| --- | --- |
| **레벨업 트리거** | 레벨업 트리거 감지. 조건 충족 시 레벨업 이벤트 발행 |
| **레벨 상태 관리** | 레벨 수치 보유 및 관리. 최대레벨 도달 여부 판단. |
| **레벨업 UX/UI** | 이펙트 재생 및 로그 출력.  |
| **레벨업 이벤트 발행** | 레벨업 이벤트를 발행하여 전역에 알림. |

**기능별 상세 규칙**

**레벨업 트리거**

> 
> 
> 
> 
> - **입력 :** 화면의 레벨업 버튼을 클릭한다.
> - **처리**
>     1. 최대 레벨 도달 여부를 확인한다. 도달했으면 레벨업을 무시하고 레벨업 프로세스를 종료한다.
>     2. [레벨 상태 관리](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)에 레벨 증가를 요청한다.
>     3. 레벨업 UX/UI
>     4. [레벨업 이벤트 발행](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)을 실행한다.
> 

**레벨 상태 관리**

> 
> 
> 
> 
> - 플레이어 레벨은 플레이어 정보 관리 오브젝트가 보유한다.
> - 레벨업 시 현재 레벨에 1을 더한다.
> - 레벨은 1 이상, 최대 레벨 이하의 범위를 유지한다.
> 
> **예외처리**
> 
> - 최대 레벨 도달 시 : 레벨업을 무시하고 로그를 출력한다.
> - 플레이어 정보 관리 오브젝트가 유효하지 않은 경우 : 로그 출력 후 크래시.
> 

**레벨업 UX/UI**

> 
> 
> 
> 
> - 레벨업 이펙트를 캐릭터 위치에 재생한다.
> - 이후 스프린트에서 “레벨업!” 토스트 알림과 화면에 표시하는 레벨 수치 UI를 추가할 예정이나 현재는 로그만 출력하여 결과를 확인한다.
> 

**레벨업 이벤트 발행**

> 
> 
> 
> 
> - 레벨업 트리거에 따라 레벨업 이벤트를 발행한다.
>     - 레벨업이 되면 이 이벤트를 구독한 대상(무기시스템, UI 등)에게 알린다.
> 

# 무기 시스템

**시스템 간단 요약**

- **장착 무기 선정** : 레벨업 이벤트가 발생하면, 데이터 테이블에서 장착할 무기를 랜덤으로 선정합니다.
- **무기 슬롯 장착** : 장착 슬롯 상태에 따라 선정된 무기를 장착합니다.
- **슬롯 상태 관리** : 장착 슬롯별 상태를 업데이트 및 관리합니다.
- **스킬 등록 요청** : 무기 장착 시 스킬 시스템에  무기 스킬을 등록 요청합니다.

**구현해야할 시스템 기능 목록**

| **시스템 구성 요소** | **설명** |
| --- | --- |
| **무기 선정** | 데이터 테이블 조회 및 랜덤 무기 선정 로직 |
| **무기 장착 슬롯 관리** | 슬롯 상태에 따른 무기 장착 로직 |
| **무기 스킬 등록** | 장착 무기의 스킬 등록. 등록된 스킬 정보 관리 |
| **무기 슬롯 데이터 및 타이머 관리** | 게임 진행에 따른 슬롯 데이터 업데이트 및 쿨타임 타이머 관리 |
| **무기 데이터 테이블** | 무기 ID, 스킬 ID, 레벨 정보 등 구조화  |

**기능별 상세 규칙**

**무기 선정**

> 
> 
> 
> 
> - **무기 선정 규칙:**
>     1. 레벨업 이벤트 발생을 확인
>     2. 게임데이터 관리 오브젝트를 통해 무기 정보 테이블 무기레벨이 1인 무기 중 1개를 확률적으로 지정
>         - 이미 보유한 무기와 중복되어도 허용 (진화/강화는 이번 스프린트에서 스킵).
>         - 다른 슬롯에 기장착된 무기의 타입이 새로 지정된 무기의 타입과 동일해도 개별적으로 장착 가능
>     3. 선택된 무기 ID를 [슬롯 관리](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)에 전달
> 

**무기 장착 슬롯 관리**

> 
> 
> 
> 
> - **무기 장착 슬롯 관리 규칙:**
>     1. 장착 가능 슬롯은 최대 3개이다.
>     2. 장착될 무기가 선정되면, 1번 슬롯부터 순서대로 빈 슬롯을 탐색한다. 
>     3. 빈 슬롯이 있으면 해당 슬롯에 무기를 장착한다.
>         - 게임데이터 관리 오브젝트를 통해 필요 데이터를 확인한다.
>             - 무기 ID를 사용해 [무기 데이터 테이블](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)에서 장착 스킬 정보(스킬 ID), 무기 외형 정보 등의 데이터를 획득한다.
>             - 스킬 ID를 사용해 [스킬 데이터 테이블](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)에 스킬 쿨타임 정보를 획득한다.
>         - 요청한 데이터를 바탕으로 [해당 슬롯의 정보](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)를 갱신 후, [스킬 등록 프로세스](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)를 진행한다.
>         - 무기 장착완료 로그를 출력한다.
>     4. 빈 슬롯이 없으면 선정된 무기를 장착하지 않고, 장착 실패 로그를 출력한다.
> 

**스킬 등록** 

> 
> 
> 
> 
> - **스킬 등록 규칙 :**
>     - 무기 시스템은 슬롯에 장착된 무기를 통해 사용할 스킬을 AMC에 등록하는 역할을 수행한다. 스킬의 발동은 관여하지않는다.
>     - 처리
>         - [슬롯 실시간 데이터](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)에 보관된 스킬 실행 단위 클래스 및 스킬 쿨타임 데이터를 확인한다.
>         - 조회된 에셋들을 동적 로드하여 플레이어 AMC에 스킬 실행 단위를 등록한다.
>         - 등록 결과로 반환된 스킬 등록 핸들을 [슬롯 런타임 데이터](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)에 보관한다.
>         - 정상 등록 시 슬롯별 무기스킬 쿨타임에 따른 타이머를 시작하여 스킬 시스템에 [스킬 발동](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)을 요청한다.
>     - 예외처리
>         - 클래스 에셋 동적 로드 실패 시 : 로그 출력 후 크래시.

# 플레이어 조작 시스템

**시스템 간단 요약**

- **플레이어 입력 감지** : 플레이어 입력을 감지하고, 입력 감지 사전 조건에 따라 입력 처리 여부를 먼저 판단합니다.
- **모드 전환** : 수동 모드 입력키로 슬롯을 자동↔수동 모드로 전환합니다. 전환 시 해당 슬롯의 쿨타임 타이머를 중지하거나 재시작하도록 무기시스템에 요청합니다.
- **직접 발사** : 수동 모드 슬롯에서 마우스 클릭 시 에임 좌표를 포함한 스킬 발동 이벤트를 스킬 시스템에 요청합니다.

**구현해야할 시스템 기능 목록**

| **시스템 구성 요소** | **설명** |
| --- | --- |
| **입력 처리** | 플레이어 입력 감지. 현재 상태에 따른 입력 처리 여부 판단 로직. |
| **슬롯 모드 관리** | 입력에 따른 모드 전환 로직. 모드 전환 시 슬롯별 쿨타임 처리 요청, 수동 모드 최대 활성 갯수 제한. |
| **수동 발사 처리** | 수동 모드의 스킬 발동 이벤트 처리 로직 |

**기능별 상세 규칙**

**입력 감지**

> 
> 
> 
> 
> - 플레이어 조작 시스템은 플레이어 입력에 따른 처리를 담당한다.
>     
>     
>     | 플레이어 입력 | 입력 맵핑 | 입력 처리 |
>     | --- | --- | --- |
>     | 이동 | WASD | 쿼터뷰 기준의 상하좌우 이동을 처리한다.  |
>     | 에임/회전 | 마우스 에임 | 마우스 에임 방향에 따라 플레이어 캐릭터의 메시가 회전한다.
>     마우스 에임 방향은 스킬 발동의 기준 방향으로도 사용된다. |
>     | 스킬 발동 | 마우스 좌클릭 | 수동 모드일때 스킬 발동을 요청한다. |

>     - 해당 슬롯에 무기가 장착되지 않은 경우 : 마우스 좌클릭, Num 1,2,3 입력 무시

>     - 입력이 감지되면, 마우스 에임 좌표를 계산한다(바닥 기준 월드 좌표)

>     - 스킬 공통 파라미터 : 생명주기(Lifetime), 쿨타임(Cooldown), 속도(Speed)
> 
> | **이동 타입** | **동작 방식** | **전용 파라미터** |
> | --- | --- | --- |
> | Linear (직선형) | 발사 방향으로 기준 속도(Speed)로 직선 비행 | 없음 |
> | Arc (곡사형) | LaunchAngle로 발사 후 GravityScale 적용 포물선 비행 | LaunchAngle, GravityScale |
> | Summon (소환형) | 이동 없이 에임 위치에서 즉시 오브젝트 생성 | 없음 |

**오브젝트 공격 판정 로직**

> 
> 
> 
> 
> - 오브젝트의 충돌 체크 및 공격방식별 데미지 판정 처리를 담당한다.
>     - 적대 캐릭터 및 배경 오브젝트를 포함하여, 실질적인 충돌 피드백이 발생하는 대상에 대해서만 판정을 수행한다.
> 
> | **타격 타입** | **대상** | **데미지 규칙** |
> | --- | --- | --- |
> | Single | 충돌 단일 대상 | 기본 데미지를 1회 적용 후 오브젝트 소멸. |
> | Pierce | 충돌 대상을 순차관통 | - 관통 발생 시마다 관통 대상에게 데미지 부여. 최대 관통회수 4회 제한.
> - 데미지 감쇄 : 관통 발생 시마다 설정된 배율(DamageDecay)만큼 데미지 감소
>   • 첫번째 대상은 데미지 100% 적용. 두번째부터 20%씩 감소.
> - 중복 타격 방지 : 동일 대상에 대한 중복 데미지 적용을 막기위해 피격 이력이 있는 대상은 리스트로 관리하여 이후의 충돌을 무시
> - 관통 제한 : 설정된 최대 관통 횟수를 모두 소진한 오브젝트는 즉시 소멸 |
> | Area | 폭발 반경 내 전체 대상 | - 범위(HitRadius) 내 모든 대상에게 데미지  부여. 
> - 중심부와의 거리에 비례하여 데미지 감쇄 적용 
>   • 범위의 30% 미만                : 데미지 100%
>   • 범위의 30% 이상 70%미만 : 데미지 70%
>   • 범윙의 70% 이상                : 데미지 40% |
> - 으브젝트 최종 데미지 산출 공식 = 기본 데미지(Amount) * 플레이어 ATK
> - 예외처리
>     - 오브젝트 클래스 로드 실패 시 로그 출력후 해당 스킬 발동 중단. 슬롯은 유지.
>

> 
> 
> 
> 
> - **테이블별 역할 정의**

> | 테이블 | 역할 | 기본키/외래키 | 관련 구성요소 |

> | Weapon_Static_Data  | 무기 장착 시 진입점 (무기 시스템 관할. 참고용) - 무기 ID → 스킬 ID 매핑.  | SkillID | 발동 및 타겟팅 |

> | Skill_Common_Resource_Data | 스킬 리소스 및 비동기 로드 에셋 관리 | SkillID | 발동 및 타겟팅 |
> | Skill_Common_Params_Data | 스킬 공통 파라미터. (생명주기, 공격 사거리 등) | SkillEffectID | 발동 및 타겟팅, 소멸 조건 |

> **데이터 로딩 시점**
> 
> | 시점 | 담당 시스템 | 로딩 내용 | 이유 |

> | 스킬 발동 시 | 스킬 시스템 | 스킬 상세 파라미터 테이블에서 요구 파라미터 조회

# 데이터 스키마

![데이터 참조 흐름.](image%204.png)

데이터 참조 흐름.

**Weapon_Static_Data**

- 설계방향
    - 무기 정보 테이블
    - 각 무기는 고유 ID로 식별되며, 무기마다 1:1 맵핑된 스킬 정보(SkillID)는 스킬 테이블과 연동된다.
    - 무기 레벨(WeaponLevel)을 통해 레벨별 무기 리스트를 필터링할 수있다.

| 컬럼명 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| WeaponID | STRING | PK, NN | 무기 고유 식별자 |
| SkilIID | STRING | FK, NN | Skill_Static_Data 참조 |
| WeaponLevel | INT | NN | 무기 레벨(필터링 목적) |
|WeaponName | STRING | FK, NN | DT_String 참조 }

**Skill_Common_Static_Data**

- 설계 방향
    - 스킬 기본 정보 테이블
    - 각 스킬은 고유 ID로 식별되며, 스킬별로 1:1 맵핑된 스킬 파라미터 정보(SkillEffectID)는 스킬 파라미터 테이블들과 연동된다.
    - 쿨타임 정보(Cooldown)을 함께 배치하여 무기시스템의 정보 조회를 간소화한다.

| 컬럼명 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| SkillID | STRING | PK, NN | 스킬 고유 식별자 |
| Cooldown | FLOAT | NN | 스킬 쿨타임 (초). 자동공격 타이머 주기로 사용 |
| SkillEffectID | STRING | FK, NN | 스킬 레벨별 파라미터 고유 식별자 |

**Skill_Common_Resource_Data**

- 설계 방향
    - 스킬 기본 리소스 데이터 테이블
    - 스킬에 사용될 어빌리티 클래스와 데미지 효과 클래스가 스킬 ID마다 1:1 맵핑되어있으며, 실시간 비동기 로드하여 사용한다.

| 컬럼명 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| SkillID | STRING | FK, NN | 스킬 고유 식별자 |
| SkillClass | SoftRef | NN | 스킬 실행 단위 클래스 에셋 소프트 레퍼런스 |
| DamageEffectClass | SoftRef | NN | 데미지 효과 클래스 에셋 소프트 레퍼런스 |
| StatusEffectClass | SoftRef |  | 상태이상 GE 클래스 에셋 소프트 레퍼런스 (선택) |

**Skill_Common_Params_Data**

- 설계 방향
    - 스킬 공통 파라미터 테이블
    - 스킬 파라미터 정보는 고유 ID로 식별되며, 여러 파라미터 테이블을 조합하여 조회할 때 사용된다.
    - 스킬 발동에 필요한 데이터를 제공한다.

| 컬럼명 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| SkillEffectID | STRING | PK, NN | 스킬 레벨별 파라미터 고유 식별자 |
| SkillType | ENUM | NN | Attack ~~/ Defense / Util~~ (현재는 Attack만 사용) |
| Lifetime | FLOAT | NN | 스킬 효과 발동 시간 (초) |
| Range | FLOAT | NN | 스킬 사용범위 |

**Skill_Attack_Common_Params_Data**

- 설계 방향
    - 공격 스킬 공통 파라미터 테이블
    - 스킬 오브젝트의 움직임/공격 판정 로직에 사용할 데이터를 제공한다.

| 컬럼명 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| SkillEffectID | STRING | FK, NN | 스킬 레벨별 파라미터 고유 식별자 |
| SpawnType | ENUM | NN | 소환 방식 -  단일형/부채꼴/원형 |
| MoveType | ENUM | NN | 이동 방식 - 근접, 직선, 유도, 궤도, 소환형 |
| HitType | ENUM | NN | 공격 방식 - 단일충돌/관통충돌/범위충돌 |
| Speed | FLOAT | NN | 스킬오브젝트 이동 속도 |
| Amount | FLOAT | NN | 기본 데미지 또는 효과 수치. 플레이어 ATK와 곱 연산으로 최종 수치 산출. |
| SpawnCount | INT | NN | 생성 오브젝트 수 |

**Skill_Attack_MoveType_Params_Arc** 

- 설계 방향
    - 공격 스킬 중 움직입 타입에 따른 곡사형 전용 스킬 데이터를 제공한다.

| 컬럼명 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| SkillEffectID | STRING | FK, NN | 스킬 레벨별 파라미터 고유 식별자 |
| LaunchAngle | FLOAT | NN | 초기 발사 각도 |
| GravityScale | FLOAT | NN | 중력 배율 |
| HitRadius | FLOAT | NN | 타격 판정 반경 |

**Skill_Attack_HitType_Params_Pierce** 

- 설계 방향
    - 공격 스킬 중 공격 타입에 따른 관통형 전용 스킬 데이터를 제공한다.

| 컬럼명 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| SkillEffectID | STRING | FK, NN | 스킬 레벨별 파라미터 고유 식별자 |
| PierceCount | INT | NN | 최대 관통 횟수 |
| DamageDecay | FLOAT | NN | 관통마다 적용되는 데미지 감쇠율 (0.0~1.0) |

**Summon_Common_Params_Data**

- 설계 방향
    - MoveType == Summon 일 경우에만 유효. 자동 타겟 탐색 및 에임 기반 소환 파라미터를 제공한다.

| 컬럼명 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| SkillEffectID | STRING | FK, NN | 스킬 레벨별 파라미터 고유 식별자 |
| SummonObjectClass | SoftRef | NN | 소환 오브젝트 클래스 에셋 소프트 레퍼런스 |
| SummonPreviewClass | SoftRef |  | 에임 장판형 전용 프리뷰 오브젝트 클래스 (선택) |
| SearchRange | FLOAT | NN | 자동 모드 타겟 탐색 범위 |
| SummonRadius | FLOAT |  | 장판 효과 범위 (선택) |

> 
> 
> 
> - 슬롯 UI는 슬롯별 쿨타임 잔여 시간과 현재 모드(자동/액티브)를 플레이어에게 표시한다.
>     - 슬롯 UI에 사용되는 데이터는 무기 시스템의 [슬롯 데이터](https://www.notion.so/Solo-Project-13-1-v1-2-3171ba272aac801e820ecd81c945363d?pvs=21)의 변화에 따라 업데이트된다.

> **표시 요소**
> 
> | 요소 | 위치 | 표시 내용 |
> | --- | --- | --- |
> | 슬롯 컨테이너 | 화면 하단 중앙 | 슬롯 3개를 가로로 배치 |
> | 무기명 | 슬롯 중앙 | 장착된 무기 이름. 빈 슬롯이면 "EMPTY" |
> | 쿨타임 오버레이 | 슬롯 위 | 쿨타임 진행 중일 때 어두운 오버레이 + 잔여 초 텍스트 |
> | 모드 표시 | 슬롯 테두리 | 액티브 모드 시 강조 테두리로 구분 |
> 
> **슬롯 상태별 표시 규칙**
> 
> | 상태 | 발생 조건 | 시각적 표현 |
> | --- | --- | --- |
> | 빈 슬롯 | 무기 미장착 | 회색 배경, "EMPTY" 텍스트 |
> | 자동공격 대기 | 비액티브 슬롯, 쿨타임 완료 | 기본 테두리, 무기명 표시 |
> | 자동공격 쿨타임 중 | 비액티브 슬롯, 쿨타임 진행 중 | 어두운 오버레이 + 잔여 초 텍스트 |
> | 액티브 모드 대기 | 액티브 슬롯, 쿨타임 완료 | 강조 테두리, 무기명 표시 |
> | 액티브 모드 쿨타임 중 | 액티브 슬롯, 쿨타임 진행 중 | 강조 테두리 유지 + 어두운 오버레이 + 잔여 초 텍스트 |

> **UI 업데이트 조건**
> 
> | 갱신 시점 | 갱신 내용 |
> | --- | --- |
> | 무기 장착 시 | 해당 슬롯 무기명 표시, 쿨타임 오버레이 초기화 |
> | 쿨타임 진행 중 | 매 프레임 잔여 초 텍스트 갱신 |
> | 쿨타임 만료 시 | 오버레이 제거 |

> - 잔여시간은 정수로만 표시한다. 쿨타임 잔여 시간이 1.0초 미만이면 "0"으로 표시한다.
