# /sync-doc — 코드 ↔ 기획서 동기화 검증

## 역할
현재 코드베이스와 기획서 사이의 불일치를 탐지하고 보고한다.

## 실행 절차

### Step 1 — 대상 범위 확인
사용자에게 검증 범위를 확인한다:
- 전체 시스템 (모든 기획서 vs 전체 코드)
- 특정 시스템 (예: "무기 시스템만")

### Step 2 — 기획서 핵심 항목 추출
대상 기획서(`_Design/Systems/`)에서 추출:
- DataTable 스키마 (컬럼명, 타입, FK)
- 함수/프로세스 흐름
- 예외처리 규칙
- ENUM 정의

### Step 3 — 코드 대조

| 검증 항목 | 확인 내용 |
|-----------|-----------|
| 구조체 필드 | 기획서 스키마의 모든 컬럼이 코드 구조체에 존재하는가 |
| FK 참조 | 기획서의 FK 관계가 코드에서 올바르게 조회되는가 |
| ENUM 값 | 기획서에 정의된 ENUM 항목이 코드에 모두 존재하는가 |
| 프로세스 흐름 | 기획서의 프로세스 순서가 코드에서 동일한 순서로 실행되는가 |
| 예외처리 | 기획서에 명시된 예외 상황이 코드에 처리되어 있는가 |

### Step 4 — 불일치 보고

```markdown
## [동기화 검증 결과]

### 🔴 코드 누락 (기획서에 있으나 미구현)
| 항목 | 기획서 위치 | 설명 |

### 🟡 기획서 미반영 (코드에 있으나 기획서에 없음)
| 항목 | 코드 위치 | 설명 |

### 🔵 불일치 (양쪽 다 있으나 내용이 다름)
| 항목 | 기획서 내용 | 코드 내용 | 권장 조치 |

### ✅ 일치 확인
- (정상적으로 동기화된 항목 요약)
```

## 후속 조치
1. 코드를 기획서에 맞춰 수정 → `/planning` 실행
2. 기획서를 코드에 맞춰 갱신 → `/update-design` 실행
3. 현재 상태 유지 (의도적 차이로 기록)
