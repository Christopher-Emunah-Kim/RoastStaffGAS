# /update-design — 기획서 리뷰 및 갱신

## 역할
기획서의 내용을 검토하고, 구현 결과나 설계 변경을 기획서에 반영한다.

## 실행 절차

### Step 1 — 갱신 범위 확인
- 어떤 기획서를 갱신하는가
- 갱신 사유 (구현 결과 반영 / 설계 변경 / 오류 수정)

### Step 2 — 현재 기획서 분석
- 버전 번호 확인
- 변경이 필요한 섹션 특정
- 다른 기획서와의 참조 관계 확인 (갱신 시 연쇄 영향)

### Step 3 — 갱신 초안 작성

**문서 규칙:**
- 선언적, 엔진 비종속 언어 사용 (UE5 전용 함수명은 기획서에 넣지 않음)
- 디자이너/아티스트가 읽을 수 있는 수준의 표현
- 데이터 스키마는 테이블 형태로 명시
- 예외처리는 상황 → 처리 형태로 명시

```markdown
## [갱신 제안] ○○_시스템_기획 v○.○ → v○.○

### 변경 사유
### 변경 내용
#### 섹션: ○○
**기존:** > (기존 내용)
**변경:** > (새 내용)
**변경 근거:** (사유)

### 연쇄 영향
### 버전 갱신
```

### Step 4 — 사용자 확인
갱신 초안을 사용자에게 제시하고 승인 후 기획서 파일을 직접 수정한다.

## 금지사항
- 기획서의 문체를 코드 스타일로 변환하지 않는다 (선언적 언어 유지).
- 연쇄 영향을 확인하지 않고 단일 기획서만 갱신하지 않는다.
